# Restic Box 0.7.0 — correctness and lifecycle fixes

This release is the complete set of fixes from two source-review batches:

- `restic-box-remaining-fixes.md` — the review of the 0.6.0 fixes bundle
  (9 items, all implemented and verified).
- `restic-box-fixes2.md` — the second source review (9 items, all
  implemented and verified).

Each item landed with a regression test; the full suite is 477 tests.

## Fixes from the first review (`restic-box-remaining-fixes.md`)

1. Stop All is re-checked before repository statistics launch — a stopped
   backup can no longer start `restic stats` or any follow-on subprocess.
2. Repository initialization always completes cleanly: diagnostics that can
   raise now run inside the worker's `try`, and the Initialize button is
   re-enabled on both success and failure.
3. Retention ownership is explicit: restic-box owns the repository named in
   its settings; the docs and comments say so, and the grouping claim about
   tags is corrected (`--group-by` is not used to fake isolation).
4. The raw TCP reachability probe is gone; connectivity is tested with the
   same SSH transport the real restic operation uses.
5. Configuration snapshots are taken under the configuration lock, so a save
   cannot race a running operation's reads.
6. Individually huge output records from restic are bounded — a single
   multi-gigabyte line can no longer be retained whole.
7. The pytest helper that looked like a test (`tests/__init__.py` setup and
   helper naming) is fixed so discovery collects only real tests.
8. GTK-dependent tests run headless where PyGObject is present, and skip
   with a clear reason where it is not.
9. Restic-dependent integration tests run against the real executable using
   disposable temporary repositories only — never a configured repository,
   never credentials, never the network.

## Fixes from the second review (`restic-box-fixes2.md`)

1. **Configuration-identity-safe bookkeeping.** Backup/check results are
   filed under a hash of the repository + sources they actually ran with
   (`config_identity`). Switching repositories shows that repository's own
   history ("never backed up" for a new one); switching back restores it.
   Per-identity histories are bounded.
2. **`.zfs` snapshot directories are excluded from actual backups** — a bare
   `--exclude .zfs` is added to every backup, unless the user deliberately
   includes a path containing `.zfs` (then their include wins), and a
   deliberately-typed `.zfs` exclude is honored and shown, not duplicated.
3. **Unified cancellation and retry scheduling.** Stop All terminates every
   live subprocess on every operation path; failed preflights back off
   exponentially (60 s doubling, capped at 6 h) instead of silently waiting a
   whole interval, and a manual trigger is never gated by the backoff.
4. **Repository lease.** Backups, checks, forgets, prunes, unlocks, mounts,
   and the snapshot browser's destructive operations all serialize through
   one exclusive lease; a busy repository refuses new work instead of racing.
5. **Mount lifecycle.** A mount takes one immutable configuration snapshot,
   refuses to start while another operation runs, and Forget/Prune refuse
   while a mount holds the repository. Unmount goes through the same
   process-termination path as Stop All.
6. **Query integrity.** `snapshots`/`ls` output is parsed line-by-line as it
   arrives (no whole-output retention cap that could silently truncate); a
   truncated, failed, or unparsable listing is an error, never an empty list;
   friendly views are rebuilt in a staging directory and swapped, so a failed
   refresh leaves the previous views intact.
7. **SFTP-capable SSH preflight.** The probe now requests the same subsystem
   restic uses (`ssh ... -s <host> sftp`), so SFTP-only servers — which
   reject shell exec but serve sftp — pass. Exit-code classification keeps
   auth failures distinguishable from missing subsystems.
8. **Directory scanning streams instead of materializing.** Planning a split
   walks directories with a closed-on-exit scandir stream rather than
   building a list of every entry; unreadable directories and files are
   recorded and reported instead of being silently treated as empty. Measured
   on a 60 000-file fixture with 326-character paths: 21 MiB peak streamed
   vs 78 MiB materialized (`restic-box-scan-memory.md`). No file-count
   limits were added to backups: per-directory planning lists stay bounded,
   and excess files remain covered by their parent unit.
9. **Honest status reporting.** Attempted-but-never-launched operations
   (failed preflight, busy repository, mount-blocked scheduled runs, crash)
   are recorded as `skipped`, `cancelled`, or `failed` with a reason, without
   moving the scheduling timestamps that decide when the next run is due. A
   failure keeps the timestamp of the last run that genuinely succeeded, and
   the tray says which happened last — e.g. "Backup skipped at …: connection
   unreachable: … (last successful backup …)". Configs written before this
   release are migrated on load.

## Packaging and runtime notes

- New module `restic_diag_log.py`: diagnostics go to a size-bounded, rotated
  log under `~/.config/restic-box/logs/restic-box.log` instead of an
  unbounded in-memory list.
- New test-only helper `tests/fakeproc.py`.
- `config.json` gains per-identity history and attempt-status fields; older
  files load unchanged (migrated in memory, rewritten on the next save).

## Deferred (by design, recorded for the next cycle)

- The Zstandard file-list cache from fix #8 of the second review: deferred
  until the correctness and lifecycle fixes have been in use.
- Prefix-sharing and bottom-up carving in the split planner: deferred
  (`restic-box-scan-memory.md` §5–6) — behavior changes, not bug fixes.

## Verification

- `unittest-parallel`: 477 tests OK, headless, no network, no real
  repositories, nothing written to `~/.config/restic-box`.
- Real-restic 0.19.1 integration tests use disposable temp repos only.
- The SSH preflight change was verified against real restic's `sftp.command`
  argv handling with an argument-dump wrapper.
